   621→Root Cause:
   622→- The error trace pinpointed: `at Icon (icon.tsx:30) at TopHeader (top-header.tsx:84)`.
   623→- The theme toggle button rendered `<Icon name={theme === "dark" ? "Sun" : "Moon"} />`.
   624→- `next-themes` useTheme() returns `theme=undefined` during SSR → server renders "Moon".
   625→- BUT next-themes injects an inline script that resolves the theme (from localStorage/system) BEFORE client hydration — so on the client's first render `theme` could already be "dark" (if user prefers dark) → renders "Sun" → MISMATCH with server's "Moon" → hydration crash.
   626→- This only manifested when the client's resolved theme differed from the server's default assumption.
   627→
   628→Fix:
   629→- Imported `useMounted` into TopHeader and gated the icon: `<Icon name={mounted && theme === "dark" ? "Sun" : "Moon"} />`.
   630→  - Server render: mounted=false → "Moon"
   631→  - Client first render: mounted=false → "Moon" (MATCHES server, no mismatch)
   632→  - After mount (useEffect/useSyncExternalStore): mounted=true → correct icon based on resolved theme (post-hydration update, safe)
   633→- Added `suppressHydrationWarning` on the button as a belt-and-suspenders measure.
